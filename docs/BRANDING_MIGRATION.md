# JourneyGo 命名升级

## 状态与范围

- 本次仅修改仓库代码、文件名、文档和新安装模板，未迁移或重启服务器。
- 统一品牌、数据库默认名称、镜像与容器名称、Compose project / volume 名称、Redis key 前缀、Celery task 名称、浏览器存储 key、CSS 类名及评测数据集名称。
- 不改写 Git 历史、不清理远端数据、不重置飞机调用额度；许可证和第三方版权声明不变。
- 文档内名称已规范化为 JourneyGo。历史服务器路径、镜像标签和容器名不能按规范化后的文本直接执行；实际旧值从运行环境和提交 `def71ad` 对应文件读取，例如 `git show def71ad:docs/DEPLOYMENT.md`。原始真机截图及 JSON 证据不改写。
- 仓库不包含的 `.env`、私有凭据、忽略的 `artifacts/`、依赖缓存及运行中镜像不属于本次替换对象。旧本地辅助脚本不能直接用于新版本发布。

## 新安装

使用当前 README 的 Demo 或 staging 命令。默认数据库角色和数据库为 `journeygo`，镜像为 `journeygo-app`。开发环境默认连接字符串也已改名；真实密码必须由环境变量传入。

## 已有环境：必须单独批准迁移

这是有状态命名变更，不能作为普通的前端覆盖发布。升级前必须确认目标、备份和停机窗口；本次未执行以下步骤。

1. 记录现有 Compose 文件链、project、容器、挂载卷、数据库角色和数据库名称、Redis DB、镜像 ID、保护配置及任务数量。不要输出密码或供应商凭据。
2. 备份 PostgreSQL、Redis 持久数据与行程文件卷，并验证恢复可用。保留原镜像和原部署文件，禁止 `down -v`。
3. 暂停新任务与付费入口，等待 API / Worker 没有活跃任务。确认 Redis broker 的待执行、未确认和延迟消息均已排空，再停止旧 API / Worker。不能把携带旧 Celery task 名称的消息交给新 Worker。
4. 原 PostgreSQL 的角色和数据库名必须由原环境变量继续显式提供，或在批准后单独迁移。更改 `POSTGRES_USER` / `POSTGRES_DB` 不会重命名已初始化数据库。
5. 新 Compose project 默认会使用新的卷名。发布前通过受限 override 将新服务的卷指向已有卷并设置 `external: true`，或完成经过验证的数据复制；不得启动一个空卷后宣称历史记录已迁移。旧服务与新服务不能同时写同一数据库或 Redis。
6. 对 Redis 应用 DB 中旧品牌前缀的持久 key 做停机迁移：先统计 key 数量与类型，再按前缀映射到 `journeygo:`。使用保持 TTL 的原子重命名，目标 key 已存在时停止核对，禁止覆盖或相加。不要修改 Celery broker 内部 key 或运行中的锁。
7. 特别核对 `journeygo:travel:flight:calls:<account_digest>`，原值必须原样保留，不能缺失、清零或从查询记录数量推算。最后一轮已验证的额度为上限 15、已用 10；迁移时以停机前实际读数为准。两个航班查询入口共用同一个计数 key。
8. 缓存、限流 key 可以在停机窗口选择保留或自然过期；付费累计计数不能过期丢失。检查事件通道、Worker task 注册名和恢复任务使用同一新版本。
9. 从根 Dockerfile 完整构建新镜像，再更新 API 与 Worker；不要把新源代码叠加到用户名称仍为旧值的镜像上。容器 UID 保持 `10001`，已有卷权限无需仅为品牌改名而递归重写。
10. 验证数据库记录、审核版本、地点地图记录及飞机计数与迁移前一致，再检查健康端点、Worker ping、事件进度、任务恢复和浏览器页面。付费功能最后恢复，不使用新查询代替计数核验。

## 浏览器状态

语言、运行时 API 地址、访问码和导航进度使用新 key。旧浏览器本地设置不会自动继承：用户需重新选择语言、输入访问码；依赖自定义 API 地址的客户端需重新设置。正式行程仍在服务端，不会因更换浏览器 key 被删除。

## 回滚

保持入口暂停，在新 Worker 无活跃任务且队列排空后停止新 API / Worker。按迁移记录反向恢复 Redis key，保留已经增加的累计调用次数；挂回同一数据卷，使用原镜像和原 Compose 链恢复。不要用旧 Redis 备份覆盖发布后的付费计数，不要删除新产生的行程记录。

## 验收范围

本地需运行后端测试、前端测试、构建、离线评测、Compose 配置解析，并检查 README 本地链接及图片。运行中数据迁移与镜像启动需要单独环境验证，不能用单元测试代替。
